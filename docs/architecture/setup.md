## 1. 原則

[ADR-019](../decisions/ADR-019-tts-engine-distribution.md) から来る4つ。**どれも実装で曲げない。**

| # | 原則 | 具体的な意味 |
|---|---|---|
| 1 | **ユーザーが選ぶまで外部通信しない** | 起動しただけでは 1 バイトも外に出さない。取得の起点は常にユーザーの操作（Network-optional の最初の適用例） |
| 2 | **取得する / しない を同等に提示する** | 「後で」を小さく灰色にしない。**既定は「取得しない」** |
| 3 | **部分的にインストールされた状態を残さない** | 確定は最後の 1 手（ディレクトリの rename）。失敗したら一時ディレクトリごと消える |
| 4 | **黙って劣化しない** | 取得しなかった / 失敗したは、どちらも「TTS 未セットアップ」として画面に出る。無音で動き続けない |

> **「取得しない」は壊れている状態ではない。** Lumi は起動し、喋らないだけである。
> この2つを UI でもログでも区別する（[core.md](core.md) §6「セットアップされていない場合と、起動に失敗した場合を区別する」）。

## 2. TTS セットアップ状態

Core が持つ。Stage は `stage.*` で受け取って**表示するだけ**。

```
                    ┌──────────────┐
   起動 ───────────▶│   unknown    │  まだ調べていない
                    └──────┬───────┘
                           │ 検出（ローカルのみ。外部通信しない）
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌────────────┐   ┌────────────┐   ┌──────────────┐
   │  detected  │   │ installed  │   │not_configured│
   │ 既存のエンジン│   │ Lumi が入れた│   │  未セットアップ │
   └────────────┘   └────────────┘   └──────┬───────┘
                                             │ ユーザーが「取得する」を選ぶ
                                             ▼
                                      ┌────────────┐  失敗  ┌────────┐
                                      │ installing │───────▶│ failed │
                                      └─────┬──────┘        └────────┘
                                            │ 成功                │ 再試行できる
                                            ▼                     │
                                      ┌────────────┐◀─────────────┘
                                      │ installed  │
                                      └────────────┘
```

`failed` は `not_configured` に戻さない。**「試して失敗した」と「まだ試していない」は違う**（前者は理由を出す）。

### 導入の状態と、プロセスの状態を混ぜない〔Phase 0 で追加〕

上の状態機械が表すのは**導入されているか**であって、**いま喋れるか**ではない。
エンジンのプロセスの状態（`stopped` / `starting` / `ready` / `failed`）は**別の軸**として持つ。

```
installed  ×  stopped   → 入っているが、まだ起動していない
installed  ×  starting  → 起動中（初回はエンジン自身のモデル取得で数分かかる）
installed  ×  ready     → 喋れる
installed  ×  failed    → 入っているのに起動できない = **壊れている**
```

**1つの enum に混ぜると「入っているのに起動できない」を表現できず、
ユーザーに「取得してください」と嘘の案内をすることになる。**
プロセスの所有と生存の規則 → [core.md](core.md) §6「所有と生存」

### 同じことを毎回聞かない

「取得する / しない」に**答えたかどうか**だけを `%LOCALAPPDATA%\Lumi\setup.json` に持つ。
答えていれば、次の起動から prompt を出さない（状態が `not_configured` のままでも黙って起動する）。

**汎用の設定ストアにしない。** 設定の保存形式は未確定（[../roadmap.md](../roadmap.md) 未確定事項 #9 / Phase 1）であり、
ここで先に決めると Phase 1 で作り直しになる。持つのは真偽値1つ。

### UI の置き場所（TTS）

**Phase 0 では `stage` ウィンドウの中のパネルとして出す**（独立ウィンドウにしない）。
理由と当たり判定の扱い → [ui.md](ui.md)「初回セットアップ UI は `stage` ウィンドウの中に置く」

## 2b. LLM / STT のセットアップ状態〔Phase 1。決定 → [ADR-023](../decisions/ADR-023-llm-runtime-and-model-acquisition.md)〕

**§1 の4原則は3つとも同じ。取得方法だけが違う。**

| | LLM（Ollama） | STT（faster-whisper モデル） | TTS（AivisSpeech） |
|---|---|---|---|
| Lumi が取得するか | **しない**（検出のみ） | **する**（同意に基づく） | **する**（同意に基づく） |
| 理由 | インストーラが可逆でない。他社ソフトの導入判断を代行しない | サイズが R1 に直撃する（数百 MB〜） | [ADR-019](../decisions/ADR-019-tts-engine-distribution.md) |
| 未導入のとき | 「LLM 未セットアップ」＋ 公式サイトの案内 | 「STT 未セットアップ」＋ 取得の提案 | 「TTS 未セットアップ」 |

**Silero VAD（ONNX）は配布物に同梱するので、セットアップ状態を持たない。**
barge-in は中核機能であり、「取得するまで遮れない」状態を作らない。

### 導入の状態（LLM）

**プロセスの状態と混ぜない**（§2 の規則をそのまま適用する）。

| 導入の状態 | 意味 | ユーザーに求める行動 |
|---|---|---|
| `unknown` | まだ調べていない | — |
| `not_configured` | **Ollama が見つからない** | 公式サイトからインストールしてもらう |
| `detected` | Ollama が見つかった | — |
| `model_missing` | **Ollama はあるが、設定されたモデルが無い** | `ollama pull <model>` を案内する |

| プロセスの状態 | 意味 |
|---|---|
| `stopped` | 127.0.0.1 の API が応答しない |
| `ready` | 応答する。**推論できる** |
| `failed` | 応答するが異常（バージョン不整合など） |

> **「入っているのに動かない」を1つの enum で潰さない。** `detected × stopped`（入っているが起動していない）と
> `not_configured`（そもそも入っていない）では、ユーザーに求める行動がまったく違う。
> ここで嘘の案内をすると、ユーザーは Lumi ではなく自分の環境を疑い始める。

### 導入の状態（STT）

TTS と**同型**（`not_configured` → `installing` → `installed` / `failed`）。
取得は §3〜§5 の経路をそのまま使う（ピン留め + サイズ + SHA-256 + 原子的なインストール + ロールバック）。

**ライブラリ既定の自動ダウンロードは無効にする。** `faster-whisper` / `huggingface_hub` は
モデルが無ければ黙って取りに行くため、原則1（ユーザーが選ぶまで外部通信しない）が
**ライブラリの都合で迂回される**。キャッシュに無ければ明示的に失敗させる。

### 起動フェーズへの反映

Phase 0 の `boot` は TTS だけを見ていた。**Phase 1 では LLM / STT / TTS の3つから導出する。**
導出は引き続き決定論的な純粋関数（[ui.md](ui.md)「起動フェーズ」）。

**「喋れるが聞けない」「聞けるが喋れない」は、いずれも正常な状態として表現できること。**

## 3. 取得元のピン留め

**取得先は設定にしない。** ユーザーが URL を差し替えられると、それは「Lumi が任意の実行体を落としてくる機能」になる。

| 項目 | 値 |
|---|---|
| 対象 | AivisSpeech Engine（**Engine のみ**。GUI アプリの AivisSpeech は取得しない） |
| ライセンス | **LGPL-3.0 単独**〔2026-08-15 確認。VOICEVOX ENGINE のデュアルライセンスのうち LGPL-3.0 のみを継承〕 |
| 配布元 | GitHub Releases `Aivis-Project/AivisSpeech-Engine` |
| バージョン | ピン留めする（Provisional。Lumi のリリースごとに更新する） |
| 実体 | `core/lumi/setup/engines.py` の `AIVISSPEECH_ENGINE` |

ピン留めする値は **バージョン / URL / サイズ / SHA-256** の4つ。

> **VOICEVOX は取得しない。** ソフトウェア利用規約が無断再配布を禁じており、
> 「Lumi が自動で取ってくる」形が許諾の範囲内かを判断できないため（fail-closed）。
> **ユーザーが自分でインストールしたものを検出して使う**（§6）。

## 4. 検証

**3つすべてを通らなければインストールしない。** 1つでも欠けたら中止してロールバックする。

| # | 検証 | 何を防ぐか |
|---|---|---|
| 1 | **URL のホストと配布元パスの固定**（`github.com/Aivis-Project/AivisSpeech-Engine/releases/download/...`）+ HTTPS | 別の配布元にすり替えられること。リダイレクト先も同様に検査する |
| 2 | **サイズ一致** | 途中で切れた取得物を掴むこと |
| 3 | **SHA-256 一致**（ピン留めした値と、取得したバイト列から計算した値） | 取得後に配布物が差し替えられること・転送中の改変 |

### ★ エンジン自身が、初回起動時にさらに外部から取得する〔2026-08-15 実測〕

**取得物の検証は「Lumi が落としてくるもの」にしか効かない。**
AivisSpeech Engine は**初回起動時に、エンジン自身の判断で**次を取得する。

| 取得元 | 内容 |
|---|---|
| `api.aivis-project.com`（AivisHub） | 既定の音声合成モデル（AIVMX） |
| HuggingFace | BERT モデル・トークナイザ |

これは Lumi の検証経路の外側であり、**Lumi は内容もハッシュも検証していない**。

設計上の帰結:

1. **同意の文言は「エンジンを取得する」だけでは足りない。** 初回起動時にモデルも取得されることを
   セットアップの説明に書く（実装: `stage/src/setup/SetupPanel.tsx`）
2. AivisHub からのモデル取得には **Aivis Project 利用規約が適用される**（[../licensing.md](../licensing.md) §3）。
   取得するのはユーザーの PC 上のエンジンであり、Lumi が代行するのではない
3. 取得された既定モデルは **ACML 1.0**〔2026-08-15 実測 → [../licensing.md](../licensing.md) §4.4〕。
   クレジット画面には、この経路で入る音声モデルがあることを書く必要がある
4. **ネットワークが無い環境ではエンジンの初回起動が失敗しうる。** 取得は成功したのに喋れない、
   という状態が起こる。Phase 1 で「エンジンは入っているが使えない」を状態として区別する

### 保証しないこと

- **ピン留めした SHA-256 は、GitHub の Release Asset API が返す `digest` を採ったものである。**
  配布元そのものが最初から改竄されていた場合は検出できない。
  検証が意味を持つのは「**ピン留めした時点の配布物と、いま落としたものが同一である**」ことについてのみ。
- **取得物が安全であることは保証しない。** ライセンス上再配布できないものを Lumi の配布物に入れないための仕組みであり、
  マルウェア検査ではない。
- **LGPL-3.0 の孫依存・同梱モデルのライセンスは未確認のまま**（[../licensing.md](../licensing.md) §7）。
  同梱しない限り Lumi の配布物には影響しないので、Phase 0 ではここまでとする。

## 5. 展開とインストール

### 展開に外部ライブラリを使わない

配布物は `.7z`（多ボリューム形式の第1ボリューム `.7z.001`）。単一ボリュームなので、**中身は完全な 7z ストリーム**である。

**Windows 内蔵の `bsdtar`（`%SystemRoot%\System32\tar.exe`, libarchive + liblzma）で展開する。**
Python の 7z ライブラリ（py7zr 等）は **LGPL であり、Core = MIT の境界に入れられない**。
外部プロセスとして OS 同梱のものを呼ぶことで、依存もライセンス上の問題も増やさない。

> `tar.exe` が無い環境（Windows 10 1803 未満）では**明示的に失敗**する。黙って別の手段を探さない。

### 原子的なインストール

```
%LOCALAPPDATA%\Lumi\engines\
├── .tmp-<random>\          ← ダウンロードと展開はすべてここ
└── aivisspeech-<version>\  ← 最後に rename で確定する。ここが在れば「完全に入っている」
```

**確定は rename の 1 手だけ。** 途中のどこで失敗しても、`.tmp-*` を消せば元に戻る。
ロールバックとは「確定前の状態を消すこと」であって、確定後の巻き戻しではない。

起動する実行体は展開後のツリーから `run.exe` を**探して**記録する（配布物の内部構造の変更に追随するため）。

## 6. 既存インストールの検出

**外部通信しない。** ローカルのパスと 127.0.0.1 だけを見る。

| エンジン | パス候補 | ポート |
|---|---|---|
| AivisSpeech | `%LOCALAPPDATA%\Programs\AivisSpeech\AivisSpeech-Engine\run.exe`, `C:\Program Files\AivisSpeech\AivisSpeech-Engine\run.exe` | 10101 |
| VOICEVOX | `%LOCALAPPDATA%\Programs\VOICEVOX\vv-engine\run.exe`, `C:\Program Files\VOICEVOX\vv-engine\run.exe` | 50021 |
| Lumi が入れたもの | `%LOCALAPPDATA%\Lumi\engines\aivisspeech-<version>\...\run.exe` | 10101 |
| **Ollama**〔Phase 1〕 | `%LOCALAPPDATA%\Programs\Ollama\ollama.exe`, `C:\Program Files\Ollama\ollama.exe`, および `PATH` | 11434 |

すでに起動しているエンジンがあれば、それを使う（二重に起動しない）。

> **Ollama のプロセスは Lumi が起動も停止もしない**（[ADR-023](../decisions/ADR-023-llm-runtime-and-model-acquisition.md)）。
> [core.md](core.md) §6 の「すでに動いているエンジンには触らない」を、**常にそちら側**に倒す。
> 検出できないケース（カスタムポート・リモートホスト・独自ビルド）は**設定で明示的に指定させる**。
> 検出を賢くして当てにいかない — 外すと「なぜか動かない」になる。

## 6b. 配布物が壊れていないかを、その PC で確かめる〔2026-08-15 追加〕

```
lumi-core.exe --self-check
```

sqlite-vec / FTS5 / PortAudio / TLS 証明書を、**実際に読み込んで**確認する。

**開発環境で通ることは、固めた後に通ることを意味しない。** ネイティブ拡張は
自動では同梱されず、しかも**入っていなくても import は成功する**。
実際に読み込むまで壊れていることが分からないため、**配布物を作った直後と、
別のマシンで動かない報告を受けたときに、これを回す。**

パッケージングの方式と理由 → [../decisions/ADR-021-sidecar-packaging.md](../decisions/ADR-021-sidecar-packaging.md)

## 7. Phase 0 でやらないこと

- **エンジンの自動更新**（ピン留めしたバージョンだけを扱う）
- **エンジンのアンインストール UI**（Phase 1 で設定 UI に入れる）

  > **「`%LOCALAPPDATA%\Lumi\engines\` を消せば済む」ではない。**〔2026-08-15 実測〕
  > エンジンは初回起動時に取得した音声モデルと BERT キャッシュを
  > **`%APPDATA%\AivisSpeech-Engine\`（Lumi の管理外）**に置く。
  > アンインストール UI を作るときは両方を対象にする。Lumi が入れていない
  > エンジンを検出して使っていた場合は**消してはならない**（ユーザーの持ち物）。

- **音声モデルの取得**（既定 Content Pack にモデルを含めない → [../licensing.md](../licensing.md) §2）
- **`Provider.attribution()` との接続**（Phase 1。Phase 0 のクレジットは Stage 側に静的に置く）
