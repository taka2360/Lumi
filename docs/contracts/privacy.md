# Privacy — 何を保存し、どう守り、いつ消すか

> **Status: Confirmed**

## 解決したい問題

**Lumi は常時マイクを開き、会話の生ログを永続化し、前面アプリを継続観測し、全操作を監査ログに残す。**

これは機能として必要である。記憶しないキャラクターは Lumi ではない。
しかし、それを**ユーザーが把握できないまま何年も貯め続ける**なら、それは記憶ではなく蓄積事故である。

このファイルが答える問いは4つ。

1. **何が**ディスクに残るのか
2. それは**どう守られる**のか。そして**何からは守られない**のか
3. **いつ消える**のか
4. ユーザーが「**全部消して**」と言ったとき、消えるものは何か

---

## 1. 保存先

**Windows: `%LOCALAPPDATA%\Lumi\`。**

| なぜ | |
|---|---|
| インストール先に置かない | アンインストールで消える場所にユーザーのデータを置かない |
| `%APPDATA%`（ローミング）に置かない | 記憶 DB はドメイン環境でサーバに同期されてよいものではない |

**1ユーザー1データ。** OS のユーザーが分かれていれば、記憶も鍵も分かれる。

## 2. 永続化されるもの — 全一覧

**この表がすべてである。** 新しい永続化先を足す実装は、**同じコミットでこの表に行を足す。**
表に無いものをディスクに書いてはならない。

| # | 何 | 場所 | 暗号化 | 保持期間（既定） | 「全部消す」の対象 |
|---|---|---|---|---|---|
| 1 | **Episode**（会話の生ログ） | 記憶 DB | **する** | **90 日** | ✓ |
| 2 | **記憶レコード**（episodic / semantic / procedural） | 記憶 DB | **する** | 期限なし（decay → archive） | ✓ |
| 3 | ベクトル（sqlite-vec） | 記憶 DB | **する** | 2 に従う | ✓ |
| 4 | FTS5 インデックス | 記憶 DB | **する** | 1・2 に従う | ✓ |
| 5 | **DomainEvent**（Kernel の事実） | イベント DB | **する** | **30 日** | ✓ |
| 6 | **監査ログ** | 監査 DB | **する** | **180 日** | ✓ |
| 7 | 設定（音声デバイス・locale・保持期間の選択） | 設定ファイル | しない | 期限なし | ✓ |
| 8 | セットアップ済みの外部資産（STT モデル・TTS エンジン） | インストール先 | しない | 期限なし | ✗（データではない） |
| 9 | 構造化ログ（structlog / SLO 計測） | ログファイル | しない | **7 日**（ローテーション） | ✓ |

### 永続化しないもの

| 何 | どこにある | なぜ書かないか |
|---|---|---|
| **マイク入力の生波形** | リングバッファのみ | 下記 §6 |
| **Lumi の出力音声** | 再生バッファのみ | 同上 |
| **発話本文を含む DomainEvent の payload** | — | Kernel の事実と会話内容を混ぜない。会話は Episode（#1）が持つ |
| **ウィンドウタイトル** | — | `user.focus_app` は取るがタイトルは取らない（[../architecture/world-state.md](../architecture/world-state.md)） |
| **Tool の生の引数** | — | 監査ログには `raw_input_digest` を入れ、生の値は残さない（[../architecture/permission.md](../architecture/permission.md) §7） |
| **画面キャプチャ** | — | Phase 4c / Phase 5 まで存在しない。導入時にこの表を更新する |

## 3. 暗号化

### する

**会話由来のデータを含む DB は、保存時に暗号化する。**

```
Lumi がランダムな DB 鍵を生成
  → OS の秘密保管に預ける（Windows: DPAPI / current user スコープ）
  → 起動時に取り出して DB を開く
```

**ユーザーはパスワードを作らないし、管理しない。** 鍵の存在を意識させない。

### 守らないもの

> **保存時の暗号化は「保存されたデータ」を守るのであって、
> 同じユーザー権限で既に実行されているソフトウェアからは守らない。**

DPAPI の鍵は current user スコープであり、**同じユーザーとして動くプロセスは同じように鍵を開ける。**
これは緩和ではなく、この方式の定義そのものである。**防げると書かない。**

| 守れる | 守れない |
|---|---|
| ディスクを直接読まれる | 同一ユーザー権限で動くマルウェア |
| DB ファイルだけを持ち出される | OS 管理者権限を持つ別プロセス |
| バックアップソフト / クラウド同期に載る | ユーザー自身がエクスポートしたファイル |
| 修理・売却した PC のディスクが読まれる | |

**脅威モデルの書き方は [security-boundaries.md](security-boundaries.md) と同じ規則に従う**——
その境界が保証しないことを必ず書く。

### 鍵を失ったら復旧できない

これは事故ではなく**設計上の帰結**である。帰結として2つ:

1. **暗号化された DB ファイルのコピーを「バックアップ」と呼ばない。** 別マシンでは開けない
2. ユーザーに提供するのは**エクスポート**である。
   **エクスポートしたファイルは平文になる。その事実を出力時に明示する**

## 4. 保持期間

**既定は期限あり。設定で延長・無期限を選べる。**

数値は §2 の表が持つ（Episode 90 日 / 監査ログ 180 日 / DomainEvent 30 日 / ログ 7 日）。

### 「忘れる」と「消える」を混ぜない

| | 対象 | 仕組み | 元に戻せるか |
|---|---|---|---|
| **忘れる** | 記憶レコード | salience の減衰 → `archived_at`（[../architecture/memory.md](../architecture/memory.md) §5） | **戻せる**（強い手がかりがあれば思い出す余地を残す） |
| **消える** | Episode / DomainEvent / 監査ログ / 構造化ログ | 保持期間の経過 | 戻せない |

**記憶レコードは保持期間の対象ではない。** 「Factorio が好き」を 90 日で消すのは忘却ではなく破壊である。
**元ログが消えても記憶は残る。**

### なぜ既定で期限を置くのか

「無期限・ユーザーが消すまで消えない」は一見すると誠実だが、**実際には誰も消さない。**
3年後に 10 GB の会話ログがあり、その中身をユーザーが把握していない状態は、
「勝手に消さない」の名のもとに作られた事故である。

**無期限を選べる**ことは重要である。ただしそれは、**ユーザーが自分で選んだ**という形で成立させる。

## 5. 消去

### 「全部消して」

**単一の操作で、§2 の表の「全部消す」列が ✓ の行をすべて消す。** 消去対象は表が定義する。

- 記憶 UI（[../architecture/memory.md](../architecture/memory.md) §8）と同じ画面から到達できる
- 実行前に、**何が消えるかを一覧で見せる**（表の行そのもの）
- 監査ログも対象に含める。**「消したこと」の記録だけが残る**

### 個別の削除

記憶 UI から、記憶レコード単位で物理削除できる。**物理削除はユーザーの明示操作でのみ**である
（[../architecture/memory.md](../architecture/memory.md) §5）。

### アンインストール時

**既定でデータを残す。** アンインストーラが「Lumi が覚えたことも削除する」を
**明示的に、既定オフで**提示する。

> **黙って消さないし、黙って残さない。**

## 6. 音声と、第三者

### 生の音声波形は永続化しない

- マイク入力はリングバッファのみ。**ディスクに書かない**
- **デバッグ用の録音経路も作らない。** 「開発時だけ」の抜け道は、そのまま出荷される
- 永続化されるのは STT 済みのテキストである

### 第三者の発話は残りうる

話者識別は実装しない（Phase 1〜9 のスコープ外。[provenance.md](provenance.md)）。したがって:

- 部屋の中の他人の発話
- スピーカーから流れた音声（YouTube 等。EchoGuard が棄却するのは **Lumi 自身の発話**だけ）

これらが STT され、Episode に残ることは**起こりうる。この限界を隠さない。**

### 帰結として Phase 2 の要件になるもの

| 要件 | なぜ |
|---|---|
| **マイクが開いていることが常に画面上で分かる** | 「聞かれていると思っていなかった」を起こさない |
| **即座にミュートできる** | 気づいた時点で止められなければ、表示に意味がない |
| Episode の閲覧・削除 | 残ってしまったものを消せる（§5） |

## 7. この方針が守られているかの検証

| 検証 | 方法 |
|---|---|
| 表に無い永続化先が増えていないか | 書き込み先ディレクトリの静的検査（[authority-matrix.md](authority-matrix.md) の検査項目に追加） |
| 発話本文が DomainEvent の payload に入っていないか | イベント payload のスキーマ検査 |
| 生波形がディスクに書かれていないか | 音声バッファを扱うモジュールにファイル書き込み経路が無いことの静的検査 |
| 「全部消して」が表の全行に到達するか | 統合テスト（各行に1件ずつ書いてから実行し、残存ゼロを確認する） |
| 保持期間の削除が動くか | 時刻を注入するテスト（**LLM を呼ばずにテストできること**） |
