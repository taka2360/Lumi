# ADR-034: 会話に必要な3つが揃うまでキャラクターを出さない

## Decision

**STT / LLM / TTS の3つがすべて使える状態になるまで、キャラクター本体を起動しない。**

1. 起動フェーズに **`blocked`** を追加する。3つのうち1つでも使えなければ `blocked` であり、
   キャラクターも吹き出しも出さない。音声入力も開かない（`ready` ゲートは [ADR-033](ADR-033-gate-voice-input-until-ready.md) のまま）
2. `blocked` のとき Stage は**セットアップ画面**を出す。**不足している項目と、それぞれの解決方法**を並べ、
   最後に **[終了]** を置く
3. **取得処理の失敗をセットアップ完了として扱わない。** `failed` は `failed` のままで、`blocked` に落ちる
4. 取得に失敗したときは、その旨を出したうえで **「再試行」と「今は取得しない」**を選べるようにする。
   再試行の回数に上限を置かない（**押すのは常にユーザー**であり、Lumi から催促はしない）
5. 「取得する / しない」を尋ねるパネルの拒否側を **「今は取得しない」**にする。
   押されたら「セットアップは完了していません」と、**次回起動時に再開できること**を伝えて終了させる
6. **「答えたかどうか」を永続化しない。** セットアップは完了するまで毎回再開する。`setup.json` は廃止する

各要素が「使える」の定義:

| | 使える |
|---|---|
| TTS | 導入の状態が `detected` / `installed` **かつ** プロセスが `ready` |
| LLM | 導入の状態が `detected` **かつ** プロセスが `ready` |
| STT | 導入の状態が `installed` |

導出は引き続き決定論的な純粋関数（`lumi/setup/state.py` の `boot_phase()`）であり、**Stage は判断しない**。

## Reason

**Lumi は会話するデスクトップキャラクターである。** 聞く（STT）・考える（LLM）・喋る（TTS）の
どれか1つでも欠けていれば、それは会話ではない。

Phase 0〜1 では「取得しない」も「取得に失敗した」も `ready` に倒し、
**キャラクターを人質にしない**という規則を置いていた。これは「喋らないだけの Lumi」「聞けないだけの Lumi」も
成立する、という前提に立っている。実際に動かすと、その前提が誤りだった。

- **STT が無い Lumi は、話しかけても無反応な絵**である。ユーザーには「壊れている」以外の解釈が無い。
  SetupPanel が小さく理由を出していても、**目の前に立っているキャラクターの方が強い**
- **LLM が無い Lumi は、聞き取った文字を出すだけの物体**になる。キャラクターが立っている状態で
  返事だけが永久に来ないのは、「未セットアップ」ではなく「故障」に見える
- 最悪なのは **TTS の取得に失敗したとき**で、キャラクターが出てしまうと
  **失敗したことが「起動できた」で上書きされる。** 原則4（黙って劣化しない）が
  「キャラクターを人質にしない」に負けていた

**未セットアップであることを、キャラクターを出さないことで表現する。** これは劣化ではなく、
「まだ起動していない」という**正しい状態の提示**である。

「取得しない」を選んだユーザーに対しても同じで、Lumi は**黙って半分だけ動いたりしない**。
「セットアップは完了していません／次回起動時に再開できます」と言って終了する。
**次に起動したとき、ユーザーは中断したところから続けられる。**

### 失敗のあとに「再試行」を出す理由

取得の失敗はほとんどが**一時的なもの**である（ネットワーク断・配布元の一時的な不調・転送の切断）。
ここで選択肢が「今は取得しない」しか無ければ、**回線が戻っただけで直る状態のために Lumi を再起動させる**ことになる。

上限を置かないのは、**押すのがユーザーだから**である。Lumi の側から聞き直す回数には
上限が要る（[ADR-019](ADR-019-tts-engine-distribution.md) 原則2 の「鬱陶しくしない」）が、
ユーザーが自分で押した再試行は催促ではない。

### 「答えたか」を覚えない理由

覚える意味は「同じことを毎回聞かない」ことにあった。これはセットアップが**任意**だったから成立していた。
必須になった以上、**答えを覚えることは「不足したまま二度と聞かない」ことと同義**であり、
ユーザーは毎回「セットアップは完了していません」だけを見せられて終わる。**出口の無い状態を作らない。**

## Alternatives

### 1. これまでどおり `ready` にして、SetupPanel で不足を伝える

**利点**: キャラクターが必ず出る。Phase 0 からの規則をそのまま維持できる。取得を拒否した人も
デスクトップに Lumi を置ける。

採らない理由は上に書いたとおりで、**「立っているのに反応しない」が壊れて見える**という
[ui.md](../architecture/ui.md) 自身の根拠が、そのまま不足状態にも当てはまるため。
`starting` の十数秒でさえキャラクターを出さないと決めているのに、
**永久に返事しない状態でキャラクターを出すのは一貫していない。**

### 2. TTS と STT だけをゲートにし、LLM は従来どおり `ready` に倒す

**利点**: Lumi が取得に関与しない要素（[ADR-023](ADR-023-llm-runtime-and-model-acquisition.md)）で
起動を止めずに済む。「待っても何も起きないなら待たせない」という §2b の規則とも整合する。

採らない。**返事が返ってこないことは、聞こえないことと同じくらい会話の破綻**である。
また「待たせない」の趣旨は*進捗の無い待機画面を出さない*ことであって、
`blocked` は待機画面ではなく**やることが書いてある画面**なので、この規則には抵触しない。

### 3. `blocked` を作らず、`setup` フェーズを使い回す

**利点**: enum が増えない。

採らない。`setup`（**質問を出していて答えを待っている**）と `blocked`（**答えは終わっていて、
不足が残っている**）は Stage が出すものが違う。1つに潰すと「どちらの画面を出すか」を
**Stage が推測する**ことになり、判断が表示層に漏れる。

### 4. `blocked` の画面から、再検出してそのまま起動できるようにする

**利点**: Ollama を入れた直後に Lumi を再起動しなくてよい。

Phase 1 では採らない。再検出だけでは足りず、**Provider の再登録とウォームアップのやり直し**が要る。
`ConversationRuntime` は起動時に1度だけ組み立てる設計なので、ここを可変にすると
「いつ何が登録されているか」が状態になる。**再起動という確実な経路がある**ため、
それに見合わない。

## Trade-offs

**受け入れるコスト**

- **取得を拒否した人は Lumi を使えない。** 「デスクトップに置いておくだけ」という使い方は無くなる
- ネットワークが無い環境では、初回セットアップを完了できない
- 3つのうち1つでも壊れると、直るまでキャラクターが出ない。**部分的にでも動いてほしい**という
  要求には応えられない
- Ollama を後から入れた場合、Lumi の再起動が要る

**得るもの**

- **キャラクターが立っている = 会話できる**、が例外なく成立する。
  「出ているのに反応しない」がユーザーの体験から消える
- 取得の失敗が**確実に見える**。`ready` に飲み込まれない（原則4がキャラクター表示より強くなる）
- 不足の提示が「小さな警告文」から「**やることが書いてある画面**」になる

## Consequences

1. [setup.md](../architecture/setup.md) §2b「起動フェーズへの反映」を全面的に書き換える。
   「待たせてよい条件は1つだけ」は**待機画面についての規則**として残し、`blocked` はその外に置く
2. [setup.md](../architecture/setup.md) §2「同じことを毎回聞かない」を削除し、
   **完了するまで毎回再開する**に置き換える。`SetupAnswers` と `paths.setup_state_file()` は消える
3. [ui.md](../architecture/ui.md)「起動フェーズ」の表に `blocked` を足し、
   「取得しないを選んだ場合も `ready`」を取り消す
4. [wire.json](../contracts/wire.json) の `enums.boot_phase` に `blocked` を足す
5. **Stage から Lumi を終了できるようにする。** `PlatformShell.quit()` と
   Tauri コマンド `shell_app_quit` を足す（→ [shell.md](../interfaces/shell.md)）
6. `ConversationRuntime._warm` は、3つのウォームがすべて終わってから音声入力を開く。
   `blocked` のままなら開かない（[ADR-033](ADR-033-gate-voice-input-until-ready.md) の
   Alternative 3 が採用側に変わる）
7. [ADR-019](ADR-019-tts-engine-distribution.md) の原則2は維持する（**ボタンは同じ大きさ・同じ重さ**）。
   変わるのは「取得しない」の**帰結**であって、選択肢の対等さではない
