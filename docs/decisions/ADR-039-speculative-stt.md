# ADR-039: 投機 STT — VAD の無音待ちと STT を重ねる

| | |
|---|---|
| Status | Accepted |
| Date | 2026-08-22 |
| Related | [../architecture/audio.md](../architecture/audio.md) §5 §7, [ADR-025](ADR-025-tts-on-gpu.md), [../measurements/phase1.md](../measurements/phase1.md), [../roadmap.md](../roadmap.md) Phase 2 |

## Context

**規則: 区間合計は p50 目標の 85% 以下**（[../architecture/audio.md](../architecture/audio.md) §7）。
残り 15% は、計測していない処理（DomainEvent の永続化・GC・スケジューリング・WS 往復）と、
**逐次処理の合計の中央値が各区間の中央値の和より大きいこと**のための予備枠である。

Phase 1 の区間合計は **1.27 s**（p50 目標 1.50 s のちょうど 85%）。
**Phase 2 で記憶検索 0.05 s を足すと 1.32 s / 88% になり、規則を破る。**

audio.md は既にこう宣言している——「そのときは『区間を追加する前にこの制約を確認する』の出番であって、
**目標を再び動かす理由にはしない**」。そして他の区間は縮まらないことが 2026-08-18 に結論済みである
（`llm_first_token` はモデルを小さくする以外に手が無く、`tts_first_audio` はエンジン側の固定費）。

つまり選べる手は「**記憶検索をクリティカルパスに直列で足さない**」か「区間を縮める」の2つしかなく、
後者は塞がっている。

## 観察 — `vad_ms` の 0.43 秒は、待っているだけの時間である

`vad_ms` = 0.43 s の実体は `min_silence_duration_ms`（400 ms）+ フレーム境界であり、
**「ユーザーが本当に喋り終わったかを見極めるために無音を待つ」時間**である
（2026-08-17 に決着。これは実装コストではなくターンテイキングの方針であり、最適化で消えない）。

ここに事実が1つある。**無音を待ち始めた時点で、発話本体の音声バッファはもう確定している。**
待っている 400 ms の間、STT は何もしていない。

## Decision

**VAD が無音の開始を検出した時点で、それまでの音声バッファに対する STT を投機的に開始する。**

1. VAD が無音の開始を検出したら、`min_silence_duration_ms` の経過を待たずに、
   **その時点までのバッファの不変スナップショットを取り、STT を開始する**（投機実行）
2. **スナップショットには世代 ID を付ける**（下記）。STT の結果はこの ID を持ち歩く
3. `min_silence_duration_ms` が経過して発話終端が確定したら、**世代 ID が一致する投機結果だけを採用する**
4. 無音が途切れて発話が続いた場合は、**世代を進める。** 古い世代の結果は照合で一致せず、
   到着しても採用されない。**続きを含めたバッファで再実行する。**
   破棄は異常ではない。エラーにせず、`stt.speculation_discarded` として数えるだけにする
5. 投機 STT は **barge-in の経路に載せない。** audio callback でも VAD 専用スレッドでもなく、
   別のワーカーで動かす（音声の3層分離を守る。[../architecture/audio.md](../architecture/audio.md) §2）。
   **ミュート判定は投機 STT の完了を待たない**
6. **投機は single-flight。** ワーカーは1本で、**同時に走る STT は常にたかだか1つ**（下記）
7. **1ターンあたりの投機回数に上限を置く**（`max_speculations_per_turn`、既定 3）。
   超えたらそのターンは投機をやめ、**発話終端の確定後に1回だけ実行する**（下記）
8. **予算表を「直列区間の表」から「クリティカルパスの表」に変える。**
   重なる区間は重なると明示し、クリティカルパスには寄与分だけを計上する
9. 計測に `critical_path_ms` と **`stt_overlap_ms`**（実際に重なっていた長さ）を新設する。
   `unaccounted_ms = total_ms - critical_path_ms` とする。
   **各区間の実測値は今までどおり全部出す**（どこが重いかを表から消さない）

### スナップショットと世代 ID — 競合を「速い方が勝つ」にしない

**投機実行は、走っている最中に入力が変わりうる。** 素朴に書くと、
STT ワーカーが読んでいるバッファに audio callback が書き足し、
どのバッファに対する結果なのかが誰にも分からなくなる。**これは最も再現しにくい種類のバグである。**

| 規則 | |
|---|---|
| **スナップショットは不変** | 投機 STT に渡すのは**コピー**である。渡した後のバッファへの追記は、そのコピーに影響しない |
| **世代 ID を付ける** | ターン ID + バッファ世代。**無音が途切れて発話が続いたら世代を進める** |
| **採用は原子的な照合** | 「確定した発話終端の世代」と「結果が持つ世代」を1回の判定で突き合わせる。**一致したときだけ採用する** |
| **曖昧なら採用しない** | 照合できない・世代が不明・タイムアウト。**いずれも破棄して現在のバッファで再実行する**（fail-closed） |

**「先に終わった結果を使う」にしてはならない。** 速さで勝敗を決めると、
**ユーザーが言っていない文で Lumi が返事をする**（1文目だけの投機結果が、
続きを含む再実行より先に到着する）。これは 2026-08-17 に
`min_silence_duration_ms` を下げなかった理由と同じ失敗である。

### 投機は有界でなければならない — キャンセルできない前提で設計する

**世代 ID は「間違った結果を採用しない」ことしか守らない。** 世代を進めるたびに新しい推論を
起動していたら、**長く喋る人ほど STT が積み上がる。** 「間」が入るたびに1本増えるからである。

**そして STT の推論はキャンセルできない。** 現在の実装は `asyncio.to_thread` で
CTranslate2 を呼んでおり（`core/lumi/providers/stt/faster_whisper.py`）、
**待っている側をキャンセルしてもスレッドは最後まで走る。**
Cancellation 契約（[../contracts/state-machines.md](../contracts/state-machines.md)）で言えば
**`non_cancellable` として扱う**のが正しい。**キャンセル要求は「結果を捨てる」以上のことをしない。**

したがって、有界性はキャンセルではなく**起動を絞ること**で作る。

| 規則 | |
|---|---|
| **single-flight** | ワーカーは1本。**投機が走っている間、次の投機を起動しない** |
| **保留は最新の1つだけ**（latest-wins） | 走行中に世代が進んだら、保留スロットを**上書き**する。キューに積まない。実行が空いたら**最新の世代だけ**を起動する |
| **1ターンあたりの上限** | `max_speculations_per_turn`（既定 3）。超えたらそのターンは投機を**やめる**。発話終端の確定後に1回だけ実行する（= Phase 1 と同じ直列動作へのフォールバック） |
| **スナップショットを解放する** | 実行が終わるか捨てられた時点で解放。保留スロットは上書き時に古い方を解放する。**世代だけ進めて参照を持ち続けない** |
| 計測 | `stt.speculation_started` / `stt.speculation_discarded` / **`stt.speculation_capped`** |

**上限に当たったターンは遅くなる。** それでよい。**上限に当たるのは「間を何度も置いて長く喋った」
ターンであり、そこでは既にユーザーが数秒使っている。** 投機が効かないことより、
推論が無制限に積み上がって**次のターン全体が遅くなる**ほうが悪い。

**`stt.speculation_capped` が頻発するなら、上限を上げる前に投機の開始条件を見直す**
（Consequences 末尾と同じ判断）。

### テスト

**LLM も実機も使わずに全部テストできること。** VAD イベントの列を注入して、決定論的に検証する。

| ケース | 期待 |
|---|---|
| 無音開始 → 終端確定 | 投機結果を採用。再実行しない |
| 無音開始 → 発話継続 → 終端確定 | 投機結果を破棄。世代を進めて再実行し、**続きを含む結果**を採用 |
| 投機結果が終端確定より**後**に到着 | 世代が一致すれば採用（遅いだけなら正しい） |
| **古い世代の結果が後から到着** | **採用しない。**`stt.speculation_discarded` が増える |
| 世代が不明 / 照合できない | **採用しない**（fail-closed）。現在のバッファで再実行 |
| 投機中に barge-in | ミュート判定は投機を待たない。**mute latency に影響しない** |
| **世代を N 回進める** | **同時に走る STT は常に 1 つ。** 保留は最新の1つだけで、中間の世代は起動されない |
| **上限（既定 3）を超える** | 投機をやめる。`stt.speculation_capped` が増え、**終端確定後に1回だけ実行する** |
| 保留スロットが上書きされる | **古いスナップショットが解放される**（参照が残らない） |

### 新しい区間の並び

```text
        ├─ vad 0.43 ────────────────┤
        ├─ stt 0.22 ────┤            (重なる。寄与 = stt_ms - stt_overlap_ms)
                                     ├ retrieve 0.05 ┤ assemble 0.03 ┤ llm ... ┤
```

| | 区間合計 | p50 目標 1.50 s 比 |
|---|---|---|
| Phase 1（直列） | 1.27 s | 85% |
| Phase 2（直列のまま記憶検索を足す） | 1.32 s | 88% ✗ |
| **Phase 2（投機 STT）** | **1.10 s** | **73%** ✓ |

数値の内訳は [../architecture/audio.md](../architecture/audio.md) §7 が唯一の定義場所。

## Reason

**この 0.22 秒は、既に払っている待ち時間の裏に完全に隠れる。** 0.22 < 0.43 だからである。
新しく速いモデルを持ってくるのでも、品質を落とすのでもなく、**遊んでいる時間に仕事を入れるだけ**である。

**そして予備枠が 15% から 27% に増える。** これが本当の利得である。Phase 2 以降、
記憶検索・Reflection・World State の更新と、クリティカルパスに載る候補は増え続ける。
85% にぴったり張り付いた状態で Phase 3 を迎えると、**次に何かを足すたびに同じ議論をやり直すことになる。**

**「破棄したときの計算が無駄になる」は、支払ってよいコストである。** 破棄が起きるのは
「無音 400 ms 未満の間が空いた」ときで、そのとき CPU / GPU は他に何もしていない。
無駄になるのは**空いている資源**であって、ユーザーが待つ時間ではない。

## Alternatives

| 案 | 利点 | 採らなかった理由 |
|---|---|---|
| **記憶検索の予算を 0.05 → 0.02 s に絞る**（FTS5 + recency のみ同期、vector は非同期で次ターンへ） | 実装が軽い | **1.29 / 1.50 = 86% で、規則は依然として満たさない。** そして検索品質を SLO のために落とすのは順序が逆（2026-08-18 に `llm_first_token` で同じ判断をしている） |
| **p50 目標を 1.6 s に緩める** | 何も作らずに済む | audio.md の「目標を再び動かす理由にはしない」という明示的な宣言に反する。2026-08-18 は**縮める努力を先にやってから緩めた**。今回は縮める手が残っているのに緩めることになる |
| **`min_silence_duration_ms` を 400 → 200 ms に下げる** | -200 ms | 2026-08-17 に実測して捨てた案。**400 ms でも既に文中で区間が切れる**（3.14 秒の2文が2区間に割れ、Lumi が1文目だけ聞いて返事を始めた）。200 ms なら読点程度の間で起きる |
| **85% 規則そのものを見直す** | 表が単純になる | 予備枠が必要な理由（計測外処理・中央値の加法性）は今も正しい。**規則が間違っているのではなく、区間の並べ方が直列だっただけである** |

## Trade-offs

**受け入れるコスト:**

- **区間が連続しなくなる。** 「各区間の終端が次の区間の始端である」という規則を、
  「連続しているか、重なると明示されているかのどちらか」に緩める。
  緩めた分は `critical_path_ms` で締める（重なりを申告せずに区間を足すと、そこが `unaccounted_ms` に化ける）
- 破棄された STT の計算が無駄になる。**GPU 0.06 s / CPU 0.92 s**（実測）
- **CPU 構成では隠れきらない。** STT 0.92 s > VAD 0.43 s なので、0.49 s がクリティカルパスに残る。
  ただしこれは**改善であって悪化ではない**（元は 0.92 s 丸ごと直列だった）。
  SLO が GPU 構成での約束であることは [ADR-025](ADR-025-tts-on-gpu.md) のまま変わらない
- 状態が1つ増える（投機中 / 採用 / 破棄）。VAD の状態機械のテストが増える
- **バッファのコピーが増える**（スナップショット）。16 kHz mono float32 の数秒分であり、
  投機を安全にする代償として受け入れる。**同時に持つのは走行中の1つと保留の1つだけ**
- **間を何度も置いて長く喋ったターンは、投機が効かず Phase 1 と同じ速さに戻る**（上限に当たるため）。
  クリティカルパスの 1.10 s は**上限に当たらなかったターンの値**である

**得るもの:**

- 予備枠が 15% → 27%。Phase 2 の記憶検索を入れても余裕が残る
- クリティカルパスに載っているものと、載っていないものが表で区別できるようになる

## Consequences

- `architecture/audio.md` §7 の区間表を、クリティカルパスの表に置き換える。
  「区間は連続していなければならない」の記述と `turn_latency` のログ例を改定する
- `turn_latency` に `critical_path_ms` / `stt_speculative` / `stt_overlap_ms` を追加する。
  **`stt` の寄与は `stt_ms - stt_overlap_ms` であり、定数 0 ではない**（CPU 構成では隠れきらない）。
  `unaccounted_ms` の定義が `total_ms - measured_sum_ms` から `total_ms - critical_path_ms` に変わる
- **`retrieve_ms` を予算表に入れてよくなる。** Phase 2 の記憶検索がクリティカルパスに載る前提で設計できる
- 実装は Phase 2 の「やること」に入る。**記憶検索を配線する前に投機 STT を入れる**
  （逆順にすると、その期間だけ 88% の状態で走ることになる）
- **STT Provider を `non_cancellable` として扱う。** キャンセル可能にする改修はこの ADR の範囲外であり、
  有界性は single-flight と上限で作る。**「そのうちキャンセルできるようにする」を前提にしない**
- 破棄率・`speculation_capped` の発生率は実測して [../measurements/phase1.md](../measurements/phase1.md) の後継に記録する。
  **破棄が頻発するなら `min_silence_duration_ms` の見直しではなく、投機の開始条件を見直す**
