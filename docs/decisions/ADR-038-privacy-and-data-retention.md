# ADR-038: 記憶データのプライバシー方針 — 保存先・暗号化・保持期間・削除

| | |
|---|---|
| Status | Accepted |
| Date | 2026-08-22 |
| Related | [../contracts/privacy.md](../contracts/privacy.md)（この決定の展開先・SSoT）, [../architecture/memory.md](../architecture/memory.md), [../architecture/permission.md](../architecture/permission.md), [../contracts/provenance.md](../contracts/provenance.md), [../roadmap.md](../roadmap.md) Phase 2 |

## Context

**Phase 2 は「ユーザーの発話を永続化する」最初の Phase である。**

Phase 1 まで、ディスクに残るのは Kernel の事実（Activity の開始・終了、Tool の3段階記録、権限判断）だけで、
**発話本文は一切永続化していない**（`core/lumi/storage/sqlite.py`）。Working Memory はセッション内メモリのみである。

Phase 2 で Episode（会話の生ログ）・記憶レコード・ベクトルが入る。ここで方針を決めずに書き始めると、
**スキーマもマイグレーションも作り直しになる。** 暗号化は後から足せない（既存 DB の移行が要る）し、
保持期間は「消す単位」がテーブル設計に現れる。「全部消したい」に応えられる構造かどうかも同様である。

同時に、Lumi は次の性質を持つ。**常時マイクを開き、会話の生ログを永続化し、
前面アプリを継続観測し、全操作を監査ログに残す。** それにもかかわらず、
現在の docs にはデータの扱いに関する方針が**どこにも無い**。

## Decision

### 1. 保存先 — OS のユーザーデータ領域に、1ユーザー1データで置く

Windows では `%LOCALAPPDATA%\Lumi\` 配下。**インストール先には置かない**（アンインストールで消える場所に
ユーザーのデータを置かない）。**ローミングしない**（`%APPDATA%` を使わない。記憶 DB はドメイン環境で
サーバに同期されてよいものではない）。

### 2. 会話由来のデータを含む DB は、保存時に暗号化する

**必須である。** 記憶 DB（Episode・記憶レコード・ベクトル・FTS インデックス）は平文で置かない。

- Lumi が**ランダムなデータベース鍵を生成**する
- 鍵は OS の秘密保管に預ける。**Windows では DPAPI（current user スコープ）**
- **ユーザーはパスワードを作らないし、管理しない。** 鍵の存在をユーザーに意識させない

### 3. 暗号化が守らないものを明記する

> **保存時の暗号化は「保存されたデータ」を守るのであって、
> 同じユーザー権限で既に実行されているソフトウェアからは守らない。**

DPAPI の鍵は current user スコープであり、同じユーザーとして動くプロセスは同じように鍵を開ける。
**防げると書かない。** 守れるのは、ディスクを直接読まれた場合・DB ファイルだけを持ち出された場合である。

### 4. 鍵を失うと記憶 DB は復旧できない

これを事故ではなく**設計上の帰結**として受け入れる。帰結として:

- **暗号化された DB ファイルのコピーを「バックアップ」と呼ばない。** 別マシンでは開けない
- ユーザーに提供するのは**エクスポート**であり、それは可搬な形式で出す。
  エクスポートしたファイルは平文になる。**その事実を出力時に明示する**

### 5. 保持期間 — 既定は期限あり。設定で延長・無期限を選べる

| 対象 | 既定 |
|---|---|
| Episode（会話の生ログ） | **90 日** |
| 監査ログ | **180 日** |
| DomainEvent（Phase 1 から貯まっているもの） | **30 日** |

**記憶レコード本体はこの表の対象ではない。** 記憶は decay して archive されるものであり
（[../architecture/memory.md](../architecture/memory.md) §5）、**期限で消えるものではない**。
両者を混ぜると「忘れる」と「消す」が同じ操作になる。

### 6. 「全部消したい」に単一の操作で応える

消去対象の一覧を [../contracts/privacy.md](../contracts/privacy.md) が**唯一の定義場所**として持つ。
新しい永続化先を足す実装は、**同じコミットでこの一覧に行を足す**。

### 7. アンインストール時は既定でデータを残す

アンインストーラが「Lumi が覚えたことも削除する」を**明示的に、既定オフで**提示する。
黙って消さないし、黙って残さない。

### 8. 第三者の音声 — 生の音声波形は永続化しない

- マイク入力の生波形は**リングバッファのみ**。ディスクに書かない。デバッグ用の録音経路も作らない
- 永続化されるのは STT 済みのテキストである
- 話者識別は実装しないので、**第三者の発話が STT され Episode に残ることは起こりうる**
  （[../contracts/provenance.md](../contracts/provenance.md) が限界として記録済み）。
  これを**隠さない**。マイクが開いていることが常に画面上で分かること、
  即座にミュートできることを Phase 2 の要件に含める

### 9. Phase 1 から貯まっている DomainEvent も「全部消したい」の対象である

Kernel の事実しか入っていなくても、`correlation_id` と時刻の連なりは会話の痕跡である。
**#6 の消去対象一覧に含める。**

## Reason

**暗号化を選んだ理由。** 記憶 DB は「ユーザーが Lumi に話したこと全部」である。
それが平文の SQLite でユーザープロファイル配下に置かれていると、
**バックアップソフト・クラウド同期・修理に出した PC・売却した SSD** が全部漏洩経路になる。
これらはいずれも「攻撃者」を必要としない。ありふれた事故で起きる。

**パスワードを作らせなかった理由。** ユーザーにパスフレーズを設定させる設計は、
「忘れたら全記憶が消える」を毎回のセッションの前提にする。デスクトップに常駐するキャラクターに対して、
起動のたびにパスフレーズを要求するのは成立しない。**保存しておけば、それは鍵をドアの横に置くのと同じ**であり、
それなら OS の秘密保管に預けるほうが正直で、実際に強い。

**保持期間に既定の期限を置いた理由。** 「無期限・ユーザーが消すまで消えない」は一見すると誠実だが、
**実際には誰も消さない。** 3年後に 10 GB の会話ログがあり、その中身をユーザーが把握していない状態は、
「勝手に消さない」の名のもとに作られた事故である。既定で期限を置き、
**望むなら無期限にできる**（その選択をユーザーが自分でした、という記録が残る）ほうが良い。

**記憶レコードを保持期間の対象から外した理由。** 「Factorio が好き」を 90 日で消すのは忘却ではなく破壊である。
記憶は salience の減衰で薄れ、archive される。**元ログが消えても記憶は残る**——これは人間と同じ構造であり、
Lumi の設計思想（覚え、忘れ、矛盾を抱える）とも一致する。

## Alternatives

| 案 | 利点 | 採らなかった理由 |
|---|---|---|
| **平文 SQLite + OS の ACL に委ねる** | 依存が増えない。sqlite-vec / FTS5 / PyInstaller の統合が確実。バックアップと移行が単純 | 上記の「ありふれた事故」を1つも防げない。**ローカル専用であることは、平文でよいことを意味しない** |
| **生ログの本文カラムだけアプリ層で暗号化** | 依存ゼロ。DB 全体の暗号化より軽い | **FTS5 の全文検索が効かなくなる。** 検索が Phase 2 の中核機能なので、これは機能を捨てるのと同じ。ベクトルとメタデータが平文で残る点も中途半端 |
| **パスフレーズ方式** | 同一ユーザー権限のマルウェアからも（入力中以外は）守れる | 起動のたびの入力要求が常駐キャラクターと両立しない。保存すれば強度は DPAPI 方式と変わらない |
| **保持期間は無期限。削除はユーザー操作のみ** | 「勝手に消さない」が徹底される | 実際には誰も消さない。把握されていないログが無限に増える |
| **初回セットアップで保存方針をユーザーに聞く** | 決定を先送りできる。TTS 取得と同じ形式 | セットアップの選択肢がさらに増える。**かつ、ここは既定を決められる。** 決められることを聞くのは、判断をユーザーに押し付けているだけである |

## Trade-offs

**受け入れるコスト:**

- **暗号化 DB と sqlite-vec 拡張・FTS5・PyInstaller の組み合わせは未検証である。**
  拡張ロードが暗号化ビルドで動くか、Windows の wheel があるか、配布物に載るかを
  **Phase 2 の最初に spike で確認する**（[../roadmap.md](../roadmap.md) Phase 2）。
  ここが通らなければ、この ADR を修正する新しい ADR が要る。**黙って平文に落とさない**
- 鍵の喪失 = 記憶の喪失。移行・バックアップ手段はエクスポートに限られる
- 保持期間の実装（期限切れの削除ジョブ）が Phase 2 のスコープに入る
- DPAPI は Windows 固有である。**鍵の保護は OS ごとの窓口として抽象化する**が、
  Windows 以外の実装は該当 Phase まで作らない

**得るもの:**

- Phase 2 のスキーマを一度で正しく作れる。暗号化・保持期間・削除単位が最初から入る
- 「全部消したい」に答えられる。これは記憶 UI（Invariant 7 の唯一の昇格経路）と同じ画面に置ける
- **Lumi が何を保存しているかを、1つのドキュメントで説明できる**

## Consequences

- **`contracts/privacy.md` を新設する。** これがデータの保存先・暗号化・保持期間・消去対象の
  唯一の定義場所になる。DESIGN.md §12 の SSoT 表と §8 の確定度表に行を足す
- 既に方針として決まっていたもの（`user.focus_app` はウィンドウタイトルを取らない /
  監査ログは `raw_input_digest` のみ / 記憶の物理削除は明示操作のみ）は、
  **privacy.md からリンクする。再掲しない**
- `architecture/memory.md` §2 のストレージ記述に、暗号化と鍵の扱いが加わる
- DESIGN.md §8 の「**DomainEvent の保持ポリシー** — 未決（Phase 3 着手前）」は、
  **この ADR で決着した**（30 日 / 全消去の対象）。Phase 3 まで持ち越さない
- Phase 2 の「やること」に、暗号化 DB の spike・保持期間ジョブ・全消去・
  エクスポート・アンインストーラの選択肢・録音インジケータが加わる
