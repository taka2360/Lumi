# ADR-019: TTS エンジンを配布物に含めず、ユーザーの明示的な選択に基づく実行時取得とする

## Decision

**Lumi は公開配布される前提で設計する。** その上で:

1. **AivisSpeech / VOICEVOX のエンジン本体を Lumi の配布物に含めない。**
2. 初回セットアップで、**ユーザーの明示的な選択**に基づき、公式配布元から AivisSpeech を取得して自動セットアップする経路を用意する。**取得しない選択を同等に提示し、取得しなくても Lumi は起動する。**
3. 取得は**検証つき**で行う（公式配布元であること・取得物の完全性）。失敗したら**黙って劣化せず**、明示的に「TTS 未セットアップ」状態にする。部分的にインストールされた状態を残さない。
4. **VOICEVOX は同梱しない**（ソフトウェア利用規約が無断再配布を明示的に禁止しているため、選択の余地がない）。ユーザーが別途インストールしたものを検出して使う。
5. **音声合成モデルは、ライセンスが再配布を許すもの（ACML 等）に限り同梱しうる。** ただし既定 Content Pack には含めずに始める。
6. **クレジット表示を Phase 0 の必須項目にする。**
7. **`Provider` interface に `attribution()` を Phase 1 で含める。**

規約の調査結果と、各項目の根拠となる条文 → [licensing.md](../licensing.md)

## Reason

### VOICEVOX は選択の余地がない

VOICEVOX ソフトウェア利用規約の禁止事項に、**「本ソフトウェアの全てまたは一部を無断で再配布すること」**が明文で入っている。公開配布する以上、個別に許諾を得ない限り同梱は違反になる。

### AivisSpeech は同梱の余地があるが、いま検証しない

AivisSpeech / Engine は Aivis Project 利用規約 第1条5項により **OSS ライセンス（LGPL-3.0 系と理解）が優先**する。LGPL-3.0 は条件付きで再配布を許すため、**同梱の余地はある**。

それでも含めないのは、次の3つを配布物単位で洗う必要があるからである。

1. LICENSE 本文（バージョン・例外条項・デュアルライセンスの有無）
2. 依存ライブラリの孫ライセンス
3. Engine に同梱される既定音声モデルの個別ライセンス

これは Phase 0 の目的（**AI 要素と無関係に失敗しうる統合点を先に全部貫通させる**）とは別軸の作業であり、混ぜると両方が遅れる。Phase 0 の失敗は「Tauri の透過が動かない」であるべきで、「ライセンスの読み込みが終わらない」であってはならない。

### 一度配布したものは取り消せない

**これが決定的な理由。** 後から違反が判明しても、既に配られたインストーラは回収できない。

対称でない賭けである。含めなかった場合の損失は「初回セットアップに1ステップ増える」で、可逆。含めて間違えた場合の損失は不可逆。**迷ったら安全側（fail-closed）に倒す。**

### なぜ「完全手動」ではなく「同意に基づく実行時取得」なのか

Phase 0 の完了条件は「別マシンでインストーラから起動し、キャラが立って一言喋る」である。ユーザーがブラウザで配布元を探して手動インストールすることを必須にすると、**常駐デスクトップキャラクターとしての導入体験が壊れる**。「PC に住んでいる AI 生命体」が、住み始める前に手順書を要求する。

再配布の禁止が禁じているのは**開発元が配ること**であって、**ユーザーが公式配布元から取得すること**ではない。取得の起点をユーザーの明示的な選択に置けば、両立する。

### なぜ「明示的な選択」でなければならないのか

[DESIGN.md](../DESIGN.md) §1 の **Network-optional**（外部通信は任意・明示的）の**最初の適用例**になるため。

同意なしに初回起動で外部へ取りに行くと、「Lumi は黙って通信する」という前提が製品の一番最初に埋め込まれる。**推論・状態・判断はローカルで完結する**という主張が、ユーザーが最初に見る30秒で嘘になる。ここで例外を作ると、Phase 4b の `browser`、Phase 5 のモデル取得でも同じ例外が求められる。

### なぜクレジット表示が Phase 0 なのか

**Phase 0 で配布物ができるから。** 義務は「配布した時点」で発生する。

VOICEVOX 音源利用規約はクレジット表記を必須とし、無い場合の商用利用を **1キャラクターあたり40万円（+税）**と定めている。VOICEVOX ソフトウェア利用規約も「VOICEVOX を利用したことがわかるクレジット表記が必要」と書く。ACML は配布時のライセンス文書添付を必須とする。

これらを Phase 1 に送ると、**クレジット無しで配布した期間**が生じる。それは遡って直せない。

### なぜ `attribution()` を Provider interface に入れるのか

`load` / `unload` / `resource_hint` を Phase 1 に入れるのと**同じ理由**。後から Provider にメソッドを追加すると全 Provider の書き換えになる。

加えて、クレジット文字列を Core にハードコードすると **Provider を差し替えた瞬間にクレジットが嘘になる**。「TTSProvider 抽象があること自体がライセンスリスクの緩和策である」（[ADR-008](ADR-008-provider-abstraction.md)）という主張は、差し替えたときに表示も追随して初めて成立する。

### 反例 — これをしないと何が壊れるか

| やってしまうこと | 壊れるもの |
|---|---|
| VOICEVOX を同梱する | 規約違反。回収不能 |
| 未確認のまま AivisSpeech を同梱する | 違反が判明したときに回収不能 |
| 同意なしに自動ダウンロードする | Network-optional 原則が初回起動で破れる。以後の全 Phase で例外が要求される |
| 取得失敗を握りつぶして無音で起動する | 「TTS が無い」と「TTS が壊れている」が区別できない。Phase 1 のレイテンシ SLO 計測が汚染される |
| クレジットを Phase 1 に送る | クレジット無しで配布した期間が生じ、遡って直せない |
| クレジット文字列を Core にハードコードする | Provider 差し替え時に表示が嘘になる |

## Alternatives

### A. エンジンを完全に同梱する

**利点**: セットアップが一発で終わる。ネットワーク不通の環境でも動く。「別マシンで起動して喋る」が最短で成立する。UX は明確に最良。

**採らない理由**: VOICEVOX は明文で禁止。AivisSpeech は検証コストが Phase 0 に乗る。そして**間違えたときに取り消せない**。

### B. 完全手動インストール（ユーザーが配布元を探す）

**利点**: 実装ゼロ。法的に最も安全。roadmap が既に用意しているエスケープハッチそのもの。

**採らない理由**: 常駐キャラクターの導入障壁として重すぎる。Phase 0 の完了条件（別マシンで一言喋る）の体験価値が失われる。なお**この選択肢は捨てていない** — 実行時取得の実装が Phase 0 を圧迫したら、ここへ退避する。

### C. TTS エンジンを Extension として配布する

**利点**: Core のライセンス境界が機構として明示される。

**採らない理由**: エンジンは外部プロセス（[contracts/security-boundaries.md](../contracts/security-boundaries.md) B5）であって Extension ではない。Extension にしても**再配布の可否は1ミリも変わらない**。機構を1つ増やして得るものが無い（設計原則 7）。

### D. ACML 特例条項に対して、生成テキストの内容分類器を挟む

**利点**: 「現実的な範囲の努力」の証跡として最も分かりやすい。

**採らない理由**: 3点。（a）レイテンシ SLO（p95 2.0s）を直接圧迫する。（b）誤検知でキャラクターが不自然に黙る方が体験を壊す。（c）**特例条項は完全性を要求していない** — 免除されるのは「技術的に完全に防ぐ」義務であって、努力そのものではない。人格プロンプト・なりすまし機能の不在・[Invariant 3](../contracts/invariants.md) による外部テキストの隔離で、まず努力の実体を作る。**必要と判断したら ADR を書いて足す。**

## Trade-offs

### 受け入れるコスト

- 初回セットアップに、取得・検証・失敗ハンドリング・ロールバックの実装が要る（Phase 0 の作業が増える）
- ネットワーク不通の環境では TTS をセットアップできない
- 公式配布元の URL 変更・配布形式変更に追随する保守が発生する
- ユーザーが取得を拒否した場合、Lumi は喋らない。**これを「壊れている」ではなく「まだセットアップされていない」として伝える UI が要る**
- クレジット表示という、Phase 0 の主目的（統合点の貫通）と無関係な UI を1つ作る

### 得るもの

- **配布物に、再配布が明示的に許諾されていないものが一切入らない。** 回収不能な違反を作らない
- Network-optional 原則が、製品の最初の画面で実証される
- 規約の再調査が必要になっても、**配布済みのものを直す作業が発生しない**
- インストーラサイズが小さく保たれる（R1）
- Ollama の同梱可否（未確定事項 #3）に同じ論法を適用できる。前例になる

### 保証しないこと

- **本 ADR は法的助言ではない。** 規約の原文を読んだ開発者の理解であり、弁護士の見解ではない
- **「別プロセスだからライセンス上の影響がない」とは主張しない**（[DESIGN.md](../DESIGN.md) §10 の既存方針を踏襲）
- ACML 特例条項への対応が「十分な努力」と評価されることを保証しない。**評価するのは権利者であり、Lumi ではない**
- `Provider.attribution()` があることは、クレジットが正しいことを保証しない。**中身を書くのは Content Pack と Provider の実装者**である

## Consequences

### ドキュメント

- **[licensing.md](../licensing.md) を新設**し、外部コンポーネントのライセンス・利用規約・配布物の構成の**唯一の定義場所**とする。[DESIGN.md](../DESIGN.md) §12 の SSoT 表に行を追加する
- DESIGN.md §10 のライセンス表は要約とし、詳細は licensing.md へリンクする
- roadmap.md の未確定事項 **#1（AivisSpeech / VOICEVOX の音声ライブラリ利用規約）が解消**する

### Phase 0 の作業と完了条件

追加:

- 初回セットアップ（TTS エンジンの取得選択 → 取得 → 検証 → セットアップ / 失敗時のロールバック）
- クレジット表示画面
- 「TTS 未セットアップ」状態の明示

完了条件が変わる:

| 変更前 | 変更後 |
|---|---|
| インストーラを作って別マシンで起動し、キャラクターが立って一言喋る | インストーラを作って別マシンで起動し、**初回セットアップを通した上で**、キャラクターが立って一言喋る。**取得を拒否しても起動する** |

### インターフェース

- [interfaces/provider.md](../interfaces/provider.md) の `Provider` に `attribution()` を追加する（Phase 1）
- [architecture/extension.md](../architecture/extension.md) §9 の Content Pack `voice.toml` に、モデルのクレジット・ライセンス情報を必須項目として追加する。**欠けていたら読み込みを拒否する**（fail-closed）

### 非目標への追加

- **実在の人物を演じる機能を作らない。** ACML 禁止事項1（なりすまし・誤解を招く利用）を構造的に回避するため

### 他の Phase への波及

- **Ollama の同梱可否（未確定事項 #3）**: 同じ論法（同梱しない / 同意に基づく取得 / 検出）を適用する。ただし別途決定する
- **Phase 5 の Vision モデル取得**: 同じ「同意に基づく取得」の経路を再利用できる
- **Phase 9 の Live2D Cubism Core**: ビルド時取得の方針（AIRI から借りる知見7）と整合する
