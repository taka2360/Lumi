# ADR-023: LLM ランタイムと推論モデルを配布物に含めず、種類ごとに取得方法を変える

| | |
|---|---|
| Status | Accepted |
| Date | 2026-08-16 |
| 関連 | [ADR-019](ADR-019-tts-engine-distribution.md), [../licensing.md](../licensing.md), [../architecture/setup.md](../architecture/setup.md), [../architecture/core.md](../architecture/core.md) §6, [../interfaces/provider.md](../interfaces/provider.md), [../roadmap.md](../roadmap.md) 未確定事項 #3 / #6 |

---

## Decision

[ADR-019](ADR-019-tts-engine-distribution.md) の4原則（**ユーザーが選ぶまで外部通信しない / 取得する・しないを同等に提示する / 部分的にインストールされた状態を残さない / 黙って劣化しない**）を、Phase 1 で必要になる推論スタックにも適用する。

その上で、**取得方法は対象ごとに変える。** 一律にしない。

| # | 対象 | 配布物 | 取得方法 |
|---|---|---|---|
| 1 | **Ollama**（LLM ランタイム） | **含めない** | **検出のみ。Lumi は取得もインストールもしない。** 未導入なら「LLM 未セットアップ」として提示し、公式サイトを案内する |
| 2 | **LLM モデル**（Qwen3 系 / Gemma3 系） | **含めない** | Ollama が管理する。**[ADR-037](ADR-037-consented-ollama-model-pull.md) により、明示同意後はLumiがローカル `/api/pull` で取得を依頼する。** |
| 3 | **Silero VAD**（ONNX） | **含める** | 同梱。数 MB・MIT・**barge-in の critical path** |
| 4 | **faster-whisper のモデル** | **含めない** | **ユーザーの明示的な選択に基づく実行時取得。** ADR-019 と同じ経路（ピン留め URL + サイズ + SHA-256 検証 + ロールバック） |

加えて:

5. **faster-whisper / huggingface_hub の自動ダウンロードを無効化する。** ライブラリ既定の「モデルが無ければ勝手に取りに行く」は、原則1（ユーザーが選ぶまで外部通信しない）を**ライブラリの都合で破る**。Lumi は取得経路を自前のセットアップに一本化し、**キャッシュに無ければ明示的に失敗させる**。
6. **導入の状態とプロセスの状態を、LLM / STT についても別の軸で持つ**（[architecture/core.md](../architecture/core.md) §6 が TTS について定めた規則を踏襲する）。
7. **配布物に含めるもののライセンスは、含める前に確認して [licensing.md](../licensing.md) に記録する**（fail-closed）。未確認のものは含めない。

---

## Reason

### なぜ Ollama だけ「取得すらしない」のか — ライセンスではなく可逆性の問題

Ollama は MIT であり、**再配布も自動取得も法的には可能である。** それでも採らない理由は3つあり、いずれも技術的・倫理的なものである。

| # | 理由 |
|---|---|
| 1 | **ロールバックが保証できない。** Ollama の Windows インストーラはシステムへのインストールと常駐プロセスの登録を伴う。AivisSpeech の「zip を1ディレクトリに展開し、失敗したらディレクトリごと消す」（[setup.md](../architecture/setup.md) 原則3）が成立しない。**部分的にインストールされた状態を残さない、を守れない** |
| 2 | **他社のインストーラを Lumi が黙って走らせるのは越権である。** サイレントインストールは技術的には可能だが、ユーザーの PC に Lumi 以外のソフトウェアを導入する判断を Lumi が代行することになる。[Invariant 1](../contracts/invariants.md)（権威は Core にあるが、それは Lumi の内部についての権威である）の精神に反する |
| 3 | **必要性が薄い。** ローカル LLM を動かす層は既に Ollama を持っていることが多い。検出で足りる場面で、取得の実装と保守を抱える理由がない（設計原則7） |

**AivisSpeech と扱いを変えるのは一貫性の欠如ではない。** 判断軸は「配布してよいか」ではなく「**失敗したときに元に戻せるか**」であり、その答えが違う。

### なぜ Silero VAD は同梱するのか

**barge-in が Lumi の中核的差別化点だから**（[roadmap.md](../roadmap.md) Phase 1「barge-in は絶対に落とさない」）。

実行時取得にすると、「モデルを取得するまで遮れない」という状態が生まれる。これは「TTS を取得するまで喋らない」とは意味が違う。喋らない Lumi は**静かなだけ**だが、遮れない Lumi は**話しかけても止まらない**。後者は壊れているように見える。

サイズは数 MB で、インストーラサイズ（R1、現在 13.1 MB）への影響は無視できる。MIT で再配布に条件が付かない。**同梱しない理由がない。**

### なぜ faster-whisper のモデルは同梱しないのか

**サイズが R1 に直撃する。** 実用的な精度の日本語モデルは数百 MB 〜 1.5 GB であり、現在のインストーラ 13.1 MB とは桁が2つ違う。

「音声で話しかける」は Phase 1 の中核機能なので、TTS と違って**取得しない選択が製品として成立しにくい**。しかしそれは「同梱する理由」にはならず、「**セットアップで最初に案内すべきもの**」という UI の問題である。

### なぜライブラリの自動ダウンロードを止めるのか

**これを止めないと Network-optional 原則が実装レベルで嘘になる。**

`faster-whisper` の `WhisperModel("small")` は、キャッシュに無ければ Hugging Face から**黙って取りに行く**。ユーザーは何も選んでいないし、進捗も出ないし、失敗理由も Lumi の語彙にならない。

ADR-019 で「同意なしに初回起動で外部へ取りに行かない」と決めたものが、**ライブラリの既定値によって迂回される。** 経路は Lumi のセットアップに一本化し、キャッシュに無ければ失敗させる。

### 反例 — これをしないと何が壊れるか

| やってしまうこと | 壊れるもの |
|---|---|
| Ollama をサイレントインストールする | 失敗時に部分インストールが残る。ユーザーの PC への導入判断を Lumi が代行する |
| Silero VAD を実行時取得にする | 取得するまで barge-in が効かない。中核機能が「あとで来る」ものになる |
| STT モデルを同梱する | インストーラが 1 GB 級になる。R1 が再燃する |
| ライブラリの自動ダウンロードを放置する | 起動しただけで外部通信が起きる。Network-optional が最初の30秒で嘘になる |
| Ollama 未導入を「起動できません」で片付ける | 「入っていない」と「入っているが起動していない」が区別できず、案内が嘘になる |
| LLM モデルのライセンスを Lumi の義務として扱う | 配布していないものの義務を負い、モデル追加のたびに配布物の検証が走る |

## Alternatives

### A. Ollama も同意に基づいて自動取得する（ADR-019 と完全に同じ扱い）

**利点**: 扱いが1つに揃い、説明が単純になる。導入体験は最良で、「起動したら全部揃っている」に最も近い。

**採らない理由**: ロールバックが保証できない。**「揃える」ために「戻せない」を受け入れるのは、fail-closed の原則と逆である。**

### B. llama.cpp を Core にリンクして Ollama 依存を無くす

**利点**: 外部プロセスが1つ減る。セットアップの問題そのものが消える。モデルファイルの管理を Lumi が持てる。

**採らない理由**: [ADR-008](ADR-008-provider-abstraction.md) の Provider 抽象と、Phase 5 の `ModelResourceManager`（VRAM 調停）の前提が変わる大きな決定であり、Phase 1 の範囲で決めるべきではない。**Ollama を選んだのは「ローカル無料優先 + 差し替え可能」であって、性能の最大化ではない。** 必要になったら `LLMProvider` を足せばよく、そのための抽象が既にある。

### C. STT モデルも Ollama のような外部ランタイムに任せる

**利点**: モデル管理を Lumi が持たなくてよい。

**採らない理由**: STT は barge-in から STT までの区間が SLO（p50 0.22 s）に直結し、**プロセスを跨ぐと計測できない区間が増える**（[ADR-003](ADR-003-audio-in-core.md) が音声 I/O を Core に置いたのと同じ理由）。faster-whisper は Core 内で動くべきである。

### D. Ollama 未導入なら Lumi を起動させない

**利点**: 「動くか動かないか」が単純になる。

**採らない理由**: [setup.md](../architecture/setup.md) 原則4 と衝突する。**TTS 未セットアップで起動できるのに、LLM 未セットアップで起動できないのは一貫しない。** Lumi は起動し、「まだ話せない」ことを明示する。Phase 0 で作った「起動フェーズ」の枠組みがそのまま使える。

## Trade-offs

### 受け入れるコスト

- ユーザーが Ollama を手動でインストールする必要がある。**Phase 1 の導入体験に段差が残る**
- Ollama の検出ロジック（インストール場所・ポート・起動有無）の保守が発生する。**検出できないケースは必ず出る**
- STT モデルの取得元をピン留めし、URL 変更に追随する保守が発生する（TTS エンジンと同じコスト）
- ライブラリの自動ダウンロードを止める分、「モデルが無い」を Lumi 自身が扱う実装が要る
- 配布物に Silero VAD が入るため、**OSS 通知の生成対象が増える**（[licensing.md](../licensing.md) §6 の依存グラフに乗せる）

### 得るもの

- **配布物に、再配布が明示的に許諾されていないものが引き続き一切入らない**
- **失敗したときに必ず元に戻せる。** Lumi が触るのは Lumi のディレクトリだけ
- インストーラサイズが小さいまま保たれる（R1）
- Network-optional 原則が、ライブラリの既定値に迂回されない
- Phase 5（Vision モデル取得）が同じ経路を再利用できる

### 保証しないこと

- **本 ADR は法的助言ではない。** 規約の原文を読んだ開発者の理解である
- **Ollama を確実に検出できることを保証しない。** カスタムポート・リモートホスト・独自ビルドは検出できない場合がある。そのときは設定で明示的に指定させる
- **推奨モデルの品質を保証しない。** 日本語会話品質と Tool Calling 品質は Phase 1 で実測する（未確定事項 #5）
- **ユーザーが選ぶ LLM モデルのライセンス遵守は、Lumi の保証範囲外である。** Lumi はモデルを配布しない。ただし Lumi が既定として案内するモデルの利用条件は [licensing.md](../licensing.md) に記録する

## Consequences

### ドキュメント

- **roadmap.md 未確定事項 #3（Ollama の同梱可否）が解消する**
- roadmap.md 未確定事項 #6（LLM / Embedding モデルのライセンス）は、**LLM については「Lumi が配布しないので配布義務は生じない」に確定**する。Embedding は Phase 2 のまま
- [architecture/setup.md](../architecture/setup.md) に **LLM / STT のセットアップ状態**を追加する（TTS と同じ「導入の状態 × プロセスの状態」の二軸）
- [licensing.md](../licensing.md) に Silero VAD（**配布物に含める**ため必須）と faster-whisper モデル、および案内する LLM モデルの利用条件を追加する

### Phase 1 の作業

追加:

- Ollama の検出と、「LLM 未セットアップ」状態の提示
- STT モデルの取得（ピン留め + 検証 + ロールバック）と、「STT 未セットアップ」状態の提示
- Silero VAD の同梱と、配布物への組み込み
- `huggingface_hub` / `faster-whisper` の自動ダウンロード無効化（`local_files_only` 相当）

### 起動フェーズへの波及

Phase 0 の `boot`（`setup` / `installing` / `starting` / `ready`）は TTS だけを見ていた。
**Phase 1 では LLM / STT / TTS の3つの状態から `boot` を導出する。** 導出は引き続き決定論的な純粋関数とする（[architecture/ui.md](../architecture/ui.md)「起動フェーズ」）。

**「喋れるが聞けない」「聞けるが喋れない」は、いずれも正常な状態として表現できなければならない。**

### 他の Phase への波及

- **Phase 2（Embedding モデル）**: 同じ論法を適用する。ONNX で数百 MB になるため、実行時取得の側になる見込み
- **Phase 5（Vision モデル）**: STT モデルと同じ取得経路を再利用する
