# ADR-026: サンプルレート変換は自前の polyphase FIR で行う

Status: Accepted
Date: 2026-08-17

| 関連 | |
|---|---|
| 設計 | [architecture/audio.md](../architecture/audio.md) §8 |
| 実装 | `core/lumi/audio/resample.py` |
| 前提 | [ADR-003](ADR-003-audio-in-core.md)（音声 I/O を Core に置く）, [ADR-020](ADR-020-split-audio-streams.md) |
| 制約 | [licensing.md](../licensing.md)（Core = MIT）, DESIGN.md §7 R1（インストーラサイズ） |
| 実測 | [measurements/phase1.md](../measurements/phase1.md) |

## Decision

デバイスレート → 16 kHz の変換を、**Kaiser 窓 windowed-sinc による polyphase FIR** で行う。
実装は numpy のみで書き、**外部リサンプルライブラリ（soxr / scipy）を追加しない。**

さらに、**VAD スレッドが使う変換器は状態を持つ**（`StreamingResampler`）。
32 ms チャンクごとにフィルタ履歴と位相を引き継ぐ。

## Reason

### 変換器が STT 精度を壊していた

Phase 1 の初期実装は「3-tap 移動平均 + 線形補間」だった。48 kHz → 16 kHz で実測したところ、
**8 kHz（新しい Nyquist）より上の成分が、ほぼ減衰せずに音声帯域へ折り返していた。**

| 入力 | 折り返し先 | 減衰 |
|---|---|---|
| 9 kHz | **7 kHz** | −5.6 dB |
| 10 kHz | **6 kHz** | −7.2 dB |
| 12 kHz | **4 kHz** | −11.3 dB |
| 20 kHz | **4 kHz** | −16.5 dB |

日本語の摩擦音（し / す / つ / しゅ / ち）はエネルギーの大半が 5〜12 kHz にある。
つまり**発話するたびに、すべての摩擦音の鏡像が子音識別帯域の上に重ねられていた。**
「認識精度がメチャクチャ悪い」の主因はここだった。

### チャンク境界も壊していた

VAD スレッドは 32 ms ぶんのリング読み出しごとに変換関数を呼ぶ。
**状態を持たない関数はチャンクごとにフィルタを再スタートする**ため、
毎秒 31 回の不連続が信号に入る。一括変換した同じ信号に対して **SNR 22.8 dB** だった。

これは「品質が少し悪い」ではなく、31.25 Hz の周期的アーティファクトを音声に重畳することである。

### なぜ soxr を採らないか

`resample.py` の当初のメモは「必要なら soxr（約 300 KB）を足す」と書いていた。**これは採らない。**

**libsoxr は LGPL-2.1 である。** Core は MIT で、PyInstaller の単一バンドルとして配布する
（[ADR-021](ADR-021-sidecar-packaging.md)）。静的リンク相当の同梱物に LGPL を持ち込むと、
再リンク可能性の提供義務をどう満たすかという問題が配布物全体に波及する。
**「Core に GPL/AGPL・非OSS を入れない」の境界を、リサンプラ1個のために曖昧にしない。**

代わりに書いた numpy 実装は約 60 行で、依存もライセンス境界も増やさない。

## Alternatives

| 案 | 利点 | 採らなかった理由 |
|---|---|---|
| **soxr を追加** | 実績のある実装。品質は最良。ストリーミング API も持つ | **LGPL-2.1。** MIT Core + 単一バンドル配布と噛み合わない |
| **scipy.signal.resample_poly** | 標準的。品質十分 | scipy は約 40 MB。**R1（インストーラサイズ）に直撃**する。リサンプラ1個のために払う額ではない |
| **PyAV（faster-whisper の推移的依存）の resampler** | 既にインストールされている | **他パッケージの推移的依存に critical path を預けることになる。** faster-whisper が依存を落とした日に音声入力が壊れる |
| **移動平均のタップ数を増やす** | 最小の変更 | 箱型窓は阻止域が −13 dB で頭打ち。タップを増やしても通過域が削れるだけで、折り返しは消えない |
| **デバイスを 16 kHz で開く** | 変換自体が不要 | **できない。** WASAPI 共有モードは mix format の1レートしか受け付けない（Phase 0 実測） |

## Trade-offs

**受け入れるコスト**

- 自前の DSP コードを持つ。テストで守る必要がある（エイリアス阻止・ストリーミング一致・レート比の一般性）
- 通過域は 6.4 kHz を超えると落ち始め、7 kHz で −1.15 dB。**遷移帯域はどこかに要る**ので、これは意図した交換
- 変換器が状態を持つ。**1インスタンス = 1リーダー**（VAD スレッド）であり、スレッドセーフではない

**得るもの**

- 折り返しが **−6 dB → −48 dB**（42 dB 改善）
- チャンク境界の不連続が **22.8 dB → 166 dB**（実質消滅）
- コストは 32 ms チャンクあたり **0.024 ms**。VAD スレッドの予算（30 ms）に対して無視できる
- 依存もライセンス境界も増えない

## Consequences

- `resample()` は純関数のまま残る（群遅延を補正し、長さは `round(len * dst / src)`）。
  TTS 出力の再生レート変換（`agent/speech.py`）もこの経路を通るので、**再生側の品質も同時に上がる**
  （それまでのアップサンプルは線形補間のみで、イメージ阻止が一切無かった）
- **連続ストリームを 1 チャンクずつ `resample()` で変換してはならない。** `StreamingResampler` を使う
- `audio.md` §8 に「サンプルレート変換」の行の根拠としてこの ADR を参照する
- STT 精度がこれでも足りない場合、次に触るのは `beam_size` とモデルサイズ
  （`DEFAULT_BEAM_SIZE = 1` / `small`）。**その判断は、この修正後に測り直してから行う**
